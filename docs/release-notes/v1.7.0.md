# v1.7.0 脚本可移植性 + 公司别名 + 来源 triage 基线

把「换台机器就跑不起来」的一类问题清零，并把公司别名从"候选列名"误用纠正为显式映射；
同时用确定性统计给 14 个来源做了一次体检，为下一批数据源接入定下判断依据。
语料口径不变：**5832 条 / 81 家 / 14 来源**，`docs/metrics.md` 与 `docs/source_health.md` 重跑零 diff。

## 新增

### 公司别名显式映射
- `src/data/normalize.py` 新增 `_COMPANY_ALIASES`：在去括号 / 去法律后缀 / 去空白 / 小写之后，
  按**精确整串**把 `字节` 收敛到 `字节跳动`。
- 不做前缀/子串匹配：`字节智能`、`字节跳动科技` 保持原样，避免把不同主体误合并。
- 明确纠正一处长期误读：`configs/dataset.yaml` 的 `company_aliases` 是**候选列名**，不是公司别名表，本轮未改动它。
- 因收敛目标就是语料中的既有写法，唯一公司数、零技能率、`docs/metrics.md` 全部零 diff。

### 来源体检基线
- 新增 [`docs/source-triage-v1.7.md`](../source-triage-v1.7.md)：14 个来源的岗位量、发布时间覆盖、
  中位 JD 长度、公司数，以及 5 个关注源的处置结论（修字段 / 标已知限制 / 待归因）。
- 体检由脚本在仓库外完成（19.6 MB / 5832 条，约 0.2 秒），结论以文件形式入库，便于复现与对比。

  只扫代码目录——文档里的路径示例是合理的，测试用 `\b` 排除 `https://` 这类协议前缀。
