# v1.8.0 美团校招/实习接入（机制就绪）+ 定位重复率

新增美团校招 / 实习爬虫并接入构建流水线；但用确定性比对证明**它和社招共用同一套 JD**，
净增只有 5 条，因此**本轮不并入语料**——先把机制留下，把判断依据写清楚。

## 新增

### 美团校招 / 实习爬虫
- 新增 `src/crawler/meituan_campus.py`：PC 版 `jobType` 过滤（`1`=校招、`2`=实习）。
- **无需登录 / cookie / 签名**（2026-11 实测）。只需一轮查询 token（`u_query_id` / `r_query_id`），
  整轮翻页复用——每页换新 token 会一直返回第 1 页（与社招同坑）。
- 字段映射：`name`→标题、`jobDuty` + `jobRequirement`→JD、`cityList`→城市、
  `refreshTime`→发布时间（走 `fmt_publish_time` 兼容毫秒串）、`jobUnionId`→`mtc_<id>`
  （缺失时用「标题+城市」哈希兜底）。
- 口径与社招一致：**只入技术类**；`jobFamily` 为空时用标题技术词兜底（接口对部分岗位不给该字段），
  丢弃非技术岗时打印分类计数。
- **未注册进构建流水线**（刻意）：产物写 `data/raw/meituan_campus_jobs.csv`（已被 `.gitignore` 覆盖），
  不参与 `merge_jobs` / `recrawl_all`。启用需 3 处注册 + 同步快照与文档常量，步骤写在模块 docstring 里。
  这样避免「注册了但数据不并入 → 谁本地跑一次爬虫，快照测试就红」的陷阱。
- 回归：`tests/test_meituan_campus.py`（7 条，不发网络请求）。

## 发现：校招技术岗与社招 JD 重叠 98.4%

`preflight_new_source.py` 体检 PASS（0 冲突 / 0 重复 / 技能覆盖仍 160/161），
但按 `text_hash = sha1(jd_clean)` 与现有语料比对：

| 指标 | 值 |
|---|---|
| 抓到技术类 | 311（校招 120 + 实习 191） |
| 清洗后唯一 JD | 306 |
| 与现有语料重复 | **301（98.4%），全部来自 `meituan` 社招** |
| 真正新增 | **5** |

**决策**：爬虫与注册保留，`data/processed/jobs.jsonl` 维持 5832 条。
为 5 条新增去改动 `job_freshness.json`、`metrics.md`、`source_health.md`、快照测试常量与
README / memory-bank 全部数字，成本远大于收益。是否并入由后续产品决策。
详见 [`docs/source-triage-v1.7.md`](../source-triage-v1.7.md) §7。
