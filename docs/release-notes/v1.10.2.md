# v1.10.2 千问精判 427 条"规则拿不准"的岗位

把流水线的 `--classify` 阶段接上：规则判不出、也不像职能岗的岗位交给千问逐条判定，
结果回流到排除清单。**再剔除 260 条**，零技能率降到 **8.0%**。

## 新增：`pipeline.mjs --classify`

- 只导出 `job_relevance.decide() == "uncertain"` 的岗位（427 条，不是全部 842 条 unknown）——
  规则已能判定的不浪费 token。
- 用 `qwen3.8-flash` 分批判定（110 条/页，4 页，约 7 分钟）。
- 判定结果 `runs/audit/unknown-verdicts.json`，`apply-relevance.py` 读取后**只采纳 `drop`**，
  `keep` / `unsure` 一律保留（宁留噪音，不误删）。

判定分布：**drop 260 / keep 136 / unsure 31**。理由样例：`职能-交付`、`职能-运营`、`职能-客服`、`职能-战略`。

零技能率从审查前的 **22.7%** 一路降到 **8.0%**：三成噪音被清掉了，剩下的基本是真·技术岗。

## 流水线补强
- 新增 `--data` 强制数据阶段：`--classify` 产生的 drop 需要重建才会生效，
  而审计只看"规则可判"的非技术岗，此时可能报 0 导致跳过。
- 零技能区间断言收紧到 `5%~13%`（原 `8%~16%`），与当前语料构成匹配。

## 验证
- 测试 383 通过；门禁 10 项全绿；快照常量同步 `4240 / 79 / 4018`。
