# v1.10.0 语料审查：剔除 1607 条非 AI/技术研发岗

对全量语料做了一次**成果审查**：逐条判断岗位是否属于「AI / 软件技术研发」范围，
把职能岗（运营/销售/财务/HR/法务…）与非软件域（硬件/结构/光学/制造/生物…）剔除。

**结论：6098 条里 1607 条（26%）不属于目标范围**，剔除后 **4557 条**，
零技能率从 22.7% 降到 **11.4%** —— 之前的"零技能偏高"有一半是这个噪音造成的。

## 判定方法（规则为主 + LLM 抽样守门）

1. **规则层**（`src/data/job_relevance.py`）：
   - 中文标题走 `job_family.classify_title`（技术标记优先，避免「产品研发工程师」误判）
   - 英文/未知标题走三层顺序判定：**强技术信号 → 角色类型词/非软件域 → 通用技术词**
     顺序是关键：`AI Operations Lead` 含 "AI" 但是运营；`Tech Lead, Autonomy Systems` 含 "lead" 但是技术岗
2. **验证层**：用千问（`qwen3.8-flash`）对未知岗位独立判定 300 条（149 条返回、131 条 keep/drop 明确），
   规则与 LLM **一致率 100%**（129/131 → 补两条强技术模式后 131/131）。
   LLM 在这里的角色是**抽样审计员**，不是全量标注工——全量跑要 30 分钟且易超时。

## 剔除机制（可 review、可复现）

- 清单：`configs/exclude_job_ids.txt`（1607 个 job_id，纯文本，能像代码一样被 review）
- 生成：`tools/apply-relevance.py`（读语料 → 调 `job_relevance.decide` → 写清单）
- 应用：`scripts/merge_jobs.py::load_exclusions()` 在合并时过滤，**不修改原始 CSV**
- 回归：`tests/test_job_relevance.py`（26 条边界用例）+ `tests/test_exclude_list.py`（清单解析）

## 副作用与已知限制
- **1609 条记为「已消失」**：这些是被主动剔除的岗位，新鲜度状态把它们当成"本轮未出现"。
  这是刻意剔除的副作用，不是自然下线；依据见 `configs/exclude_job_ids.txt`。
- **424 条 `uncertain` 保留**：规则判不出、也不像非技术岗（如「管培生」）——宁可留噪音也不误删。
- `meituan_campus` 反而从 5 条涨到 19 条：此前它与社招技术岗 JD 重复被去重，社招重复行剔除后它得以保留。
- 零技能占比区间断言同步收紧到 `8%~16%`（原 `20%~28%`）；放宽会掩盖"又混进非技术岗"。
