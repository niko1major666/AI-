### 接入时踩到并写进代码的坑
- **哔哩哔哩**：`X-CSRF` token 由 `api/auth/apply/csrf/token` 免登录签发，过期返回 `code=-3` → 自动刷新重试一次；社招/校招只差路径前缀。
- **滴滴**：`size` 上限 **100**。传 200 返回 `meta.code=10039`「拦截返回」+ `data=null`，但 **HTTP 仍是 200** —— 只看状态码会误判「没有岗位」。爬虫校验业务码，并对「空页但 `len(rows) < total`」显式抛错。
- **美团**：① 分页参数必须嵌在 `page` 对象里（PC 版同名接口收顶层 `pageNo` 且 `pageSize` 锁死 20；移动版 `pageSize` 实测上限 1000，爬虫固定用 200）；② `u_query_id` / `r_query_id` 是「本次查询」token，**整轮翻页必须复用** —— 每页换新会被当成新搜索、永远返回第 1 页（17 页只拿到 200 条唯一岗位，`totalCount` 却一直是 3231，看起来「抓满了」其实是重复）；③ `jobShareType=2` 免 token 但正文全空，固定用 `1`。

## 新增工具与测试
- **`scripts/preflight_new_source.py`**：加数据前的只读体检（~2s，有 FAIL 退出码 1）。把「接入后常量/阈值/文档一起红」的判断前移：清洗结构、`job_id` 冲突（`merge_jobs` `keep=first` 会静默丢行）、正文跨源重复（公司归属由 `FILES` 顺序决定）、公司写法分裂、新源零技能率、**合并后**零技能占比（20%~28%）与技能覆盖（≥159）、must 偏移（±3pt）、CSV 自带 skills 的词表缺口。现有语料自检可精确复现当期口径；SOP 见 `memory-bank/dataOnboarding.md`。
- 三个侦察脚本 `scripts/probe_{bilibili,didi,meituan}.py`：复现接口定位、分页上限、token/CSRF 行为与全站类别分布（含 `--size/--token/--share/--campus/--net`），供后来者不用重新逆向。
- 新增 `tests/test_preflight_new_source.py`（9）、`tests/test_bilibili.py`（14）、`tests/test_didi.py`（14）、`tests/test_meituan.py`（17），覆盖 CSRF 重试、分页拦截、token 复用、类别过滤与 CSV 落地。
