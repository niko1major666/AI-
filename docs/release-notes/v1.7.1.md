# v1.7.1 快手发布时间字段修复 + 零技能归因

补掉 v1.7.0 triage 里发现的两个问题：**快手社招 `publish_time` 被写死为空**（代码缺陷，非源缺失），
以及**零技能率高到底该不该动阈值**——归因给出了明确答案：不该。

## 修复

### 快手社招发布时间全部丢失
- **根因**：`src/crawler/kuaishou.py::to_rows()`（社招列表分支）把 `publish_time` 硬编码为 `""`，
  而校招分支一直读 `releaseTime`。所以 1395 条社招岗位里只有少量校招行有发布时间，
  报告里表现为「发布覆盖 17.3%」。
- **修复**：社招改为按 `releaseTime → publishTime → createTime` 顺序取值，统一走
  `src/crawler/util.py::fmt_publish_time`（毫秒时间戳与日期串都能归一）。
  三者都缺失时保持空字符串——**不猜、不拿抓取时间冒充发布时​间**。
- **回归**：新增 `tests/test_kuaishou.py`（5 条），覆盖候选字段、毫秒格式化、缺字段留空、校招分支可导入。
- **验证边界**：覆盖率是否真的上升，只有下一次真实抓取才能证明；本轮 `docs/source_health.md`
  数字**不变**（数据未变），不要用修复 PR 声称"覆盖率已提升"。

## 新增

### 零技能归因工具
- 新增 `scripts/triage_zero_skill.py`：把「零技能岗位」拆成三类，口径**直接复用**
  `scripts/source_health.py::zero_skill_job_ids`，因此结果与报告里的 32.5% / 37.4% 必然一致。
  - `nonTech`：标题命中职能词（运营/产品/销售/税务/合规…）且不含技术标记
  - `suspectedVocabGap`：标题不是职能岗，但 JD 里有英文技能样 token——最可能是词表缺口
  - `manual`：其余，需人工看样例
  - 技术标记优先：`产品研发工程师` 这类不会被误判成职能岗。
- 结论写进 [`docs/source-triage-v1.7.md`](../source-triage-v1.7.md) §4。

## 结论：零技能率不需要调阈值

| 源 | 岗位 | 零技能 | 非技术岗 | 疑似词表缺词 | 待人工 |
|---|---|---|---|---|---|
| 快手 | 1395 | 454（32.5%） | **361（79.5%）** | 50（11.0%） | 43（9.5%） |
| 小红书 | 1283 | 480（37.4%） | **363（75.6%）** | 79（16.5%） | 38（7.9%） |

企业官网同时挂技术岗与职能岗，职能岗天然抽不到技术技能。因此：

- **不改阈值、不改判定口径**：放宽只会掩盖语料构成。
- **不盲目扩词表**：快手缺口 token 是 `office / excel / roi / sop / gmv / erp / cad / hrbp`，
  是业务岗词汇，塞进技术技能表会污染匹配与技能画像。
- **真缺口很小**：小红书 `ios / android / swift / objective-c / sdk` 合计 40+ 条，值得单独核对别名。
- **下一步（v1.8.0）**：给岗位加「技术 / 非技术」标签，让 `source_health` 同时输出
  「技术岗零技能率」，把这个指标变成可行动信号。

## 验证
- 测试 **323 → 328**（326 快测 + 2 慢测），覆盖率 **65.20% → 66.30%**（门槛 55%，CI 矩阵未变）。
- 门禁 10 项全绿；`docs/metrics.md` / `docs/source_health.md` 重跑零 diff（本轮不动数据）。
- 未改：`skill_taxonomy.yaml`、零技能判定口径、阈值、公开字段语义、隐私与上传限制。

  届时按「源缺字段」处理并在本文档记录，不再尝试从抓取时间推断。
