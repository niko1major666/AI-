# v1.3.1 首屏冷启动与 3.10 CI 修复

纯性能与工程补丁：把首屏「全语料抽取」的逐 token 正则扫描换成字面量查找、把 sklearn 从默认首屏移走，本机首屏 32s → 3.9s；同时修掉 Python 3.10 上 AppTest 撞 240s 超时的真因（覆盖率逐行追踪放大 Python 层循环），3.10 恢复跑全量用例。**线上产品行为、抽取/匹配指标、词表与语料均无变化。**

## 性能
- **抽取：逐 token 正则 → `str.find`**（`src/extractor/rule_baseline.py`）：非 ASCII（中文）token 的正则 pattern 本就是 `re.escape(token)`，与 `str.find` 等价；ASCII token 只多一个「前后不是字母数字」的词边界断言，改用两次字符判断。步进规则与 `re.finditer` 对齐（命中后从末尾继续、边界失败只前进 1 字符），「最长优先 + 已占用区间不重复计数」逻辑未动
  - 全语料 **4582 条 JD 抽取 24.31s → 1.56s（15.6×）**（同机 Python 3.12）
  - 输出与旧实现**逐条一致**：4582 条的 span（skill_id/start/end）顺序与提及次数 counts 完全相同
- **`sklearn` 按需加载**（`src/app/app.py`）：`load_core()` 只建词表 + 抽取器，新增 `load_engine()`（TF-IDF 匹配 + 差距分析）仅供「简历匹配」「差距报告」页调用；`sklearn` 冷导入本机要 4.5s，默认首屏「技能图谱」不再付这笔钱
  - AppTest 首屏（含全语料抽取）：**8.83s → 3.91s**；相对优化前（推算 ~31s）约 **8×**
  - CI `test (3.10)` 单 job **85s → 41–57s**
- 新增 `scripts/bench_extract.py`：`python scripts/bench_extract.py [--limit N]` 复现全语料抽取耗时

## 修复
- **Python 3.10 的 AppTest 240s 超时**（真因，不是 AppTest 挂起）：`pytest --cov` 在 3.10 走 `sys.settrace` 逐行追踪，把首屏约 165 万次 Python 层 `re.finditer` 放慢约 15 倍（实测正则 5.8k 次/秒；3.12 的 PEP 669 `sys.monitoring` 为 80k 次/秒，只慢 1.3 倍），首屏 14.5s 膨胀到 ~240s，正好撞 `default_timeout=240`
  - CI 上 3.10 **只跑用例不传 `--cov`**（含 3 个 AppTest），覆盖率门槛 `--cov-fail-under=55` 保留在 3.12；`tests/test_app.py` 里的版本 skip 已删除
  - 两个 job 都加 `timeout-minutes: 20`，避免卡死时白占 runner

## 测试
- 新增 `test_iter_matches_equivalent_to_regex_reference`：以旧正则实现为参照，对全部 359 个 token × 7 段边界文本（`Google/go`、`c++14`、`python3`、`tensorflow2`、无空格连写、空串）**逐位置比对**，永久锁死语义
- 新增 `test_mention_count_respects_word_boundary_and_repeats`：`Python9` 不计、`python3`（词表别名）只计 1 次
- 测试 **201 → 203**（快测 199 → 201 + 2 个 slow）；本地 `pytest -m "not slow"`、`validate_kb.py`（161/6/106）、`compileall` 全绿
