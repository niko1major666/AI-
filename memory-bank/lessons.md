# 经验与陷阱（Lessons）

> 记录那些"看起来对、实际错"的判断，避免同一类错误重复付费。
> 每条都附**当时怎么发现的**，因为下次你未必有同样的运气。

## 1. 不要从一页数据外推全集

**事件（v1.8.0）**：美团校招接口第 1 页 100 条里技术类 42 条，我据此推断"技术类约 63 条"，
并写进了计划。实际全量 198 + 381 条里技术类有 **311 条**。

**规则**：分页接口的**首页分布不代表全量**。要报数，就遍历完再报，或者明说"这是首页样本"。

## 2. "去重后只剩几条"先查去重键，别急着下结论

**事件（v1.8.0）**：311 条校招并入后只剩 5 条，我先怀疑"JD 模板化"，
又怀疑"清洗把文本压成一样"。实测：清洗后仍有 **306 段唯一 JD**，真正原因是
`sha1(jd_clean)` 与 **社招 301 条完全相同**（校招/社招共用同一套 JD）。

**规则**：先算 `distinct(清洗后文本)` 与"与旧语料的交集"（本仓库有 `tools/jd-overlap-check.py`），
再谈模板化或清洗问题。

## 3. 测试失败先看它读的是哪个文件

**事件（v1.8.0）**：`test_dataset_snapshot` 报 `5837 == 5832`，我一度以为语料被污染。
实际是 `data/processed/build_stats.json`（gitignored 的构建统计）还是上一次带校招数据的版本，
而测试在它**存在时**才做二次断言。

**规则**：gitignored 的派生文件（`build_stats.json`、`all_jobs.csv`）会"记住"上一次构建，
改了数据又回滚时**必须一起清理**，否则本地红、CI 绿，最难查。

## 4. 半注册的新数据源会变成地雷

**事件（v1.8.0）**：把爬虫注册进 `merge_jobs.FILES` 却不并入数据，
导致**任何人本地跑一次爬虫，快照测试就红**（5837≠5832）。CI 是干净克隆所以永远绿——
最坏组合：本地红、CI 绿。

**规则**：要么完整接入（注册 + 同步所有常量与文档），要么**完全不注册**，
并在模块 docstring 写明"启用需要哪几处注册"。不存在"注册了但不生效"的安全中间态。

## 5. 门禁必须真的在检查东西

**事件（v1.7.0）**：`git diff --check`（无参数）在干净工作树下**什么都不检查**，
是个恒真门禁；它漏掉了 `install_playwright.ps1` 末尾多出的空行。

**规则**：每个门禁都要能举出一个"它曾经拦住过的问题"。拦住过的是门禁，
没拦住过的是装饰。`agent-team` 已改为 `git diff --check %BASE%..HEAD`。

## 7. 批量数字替换会污染"历史行"（v1.10.3）

**事件**：为同步语料数字，我写脚本全局替换 `5832`/`81 家`/`21.5%` 等，
结果把 README 里**历史周表**（`| W8 |`、`| W17 |` …）也改了——v1.4.0 那行从
「5832 条 / 81 家 / 21.5%」变成了「4240 条 / 79 家 / 8.0%」，即**篡改了发布史**。

**规则**：
1. 批量替换必须**排除历史区段**（changelog、release notes、周表）。
2. 替换后跑一次「历史行 vs 基线比对」：`tools/check-history-rows.mjs`
   （读 `git show <基线>:README.md`，逐行比对 `| W.. |` 行，输出不一致列表）。
3. 修法不是手工改，而是**从基线恢复**：`tools/fix-history-rows.mjs`。
4. 判断标准：历史文章记录的是"当时的数字"，任何同步都不该动它。



## 8. 「别名没写对」经常其实是「整族词条不存在」（v1.11.0）

**事件**：v1.7.1 起一直挂着「小红书 `ios/android/swift/objective-c/sdk` 约 40+ 条待核别名」。
真正去核对时发现：词表 161 条里**一条移动端技能都没有**——不是别名拼错，而是这一族从未建过。
按「疑似词表缺词」口径统计，小红书 59 条零技能里 44 条（74.6%）属于这一类，
top missing token 是 ios 17 / android 8 / swift 7 / objective-c 5。

**规则**：
1. 核对别名前先确认**技能族是否存在**（`grep` 词表 / `py -c` 打印 category），再谈别名拼写。
2. 用脚本算证据：`tools/zero-skill-attribution.py` 的 `topMissingTokens` 比人眼翻 JD 可靠，也能区分「非技术岗 / 缺词 / 待人工」。
3. 补词条后必须重跑 `scripts/eval_all.py`，同时看**金标 F1** 与 **TF-IDF 匹配**两处（新 token 可能抢走匹配位次）。

## 9. 技能名里的通用词会污染 TF-IDF 匹配（v1.11.0）

**事件**：新增技能初版命名为「iOS 开发 / Android 开发」，「开发」是 JD 里的高频通用词。
TF-IDF 字符 n-gram 把它算成强信号，把 `resume_sentence` gold 里
「用面向对象的语言开发企业级后台系统 → Java」这条 query 的 top-5 位次挤掉，
Recall@5 从 0.2200 掉到 0.2000（刚好卡在 2pt 容差线上）。

**规则**：
1. 技能 `name` 用**专有名词**（iOS / Android / Kotlin / Flutter），通用词只放 `aliases`，或干脆不放。
2. 词表改动后先跑 `python scripts/eval_all.py` 看 §2 匹配表；只看抽取 F1 会漏掉这类回归。
3. 匹配指标「刚好不超容差」不算通过——要找根因，而不是把容差当预算花掉。

## 6. 凭据只从仓库外读

**事件（v1.8.0）**：用户提供美团 cookie，实测接口**匿名可用**，凭据完全不需要。
若当时直接把它写进爬虫，就会永久留在 git 历史里。

**规则**：先证明"是否真的需要登录态"；需要时凭据只从环境变量或仓库外文件读取，
并由 `tools/repo-audit.mjs` + `tests/test_no_hardcoded_paths.py` 兜底。
